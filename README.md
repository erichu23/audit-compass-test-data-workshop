# Audit Compass 测试数据工作坊

浏览器内运行的测试数据生成及综合分析报告核验工具。主档、流水、工商测试数据、计算、Excel/ZIP/Word 导出均在本机浏览器完成，无业务后端或数据库。

## 数据说明

内置企业名称用于测试，交易、关联关系、人员及工商风险信息为测试样本，不代表相关企业的真实交易、关联关系或风险。内置样本会随页面源代码一起发布。用户自行导入的数据仅在浏览器中处理，不会通过应用接口上传；完整项目需使用“保存项目”下载后保管。

## GitHub Pages 部署

1. 新建仓库 `audit-compass-test-data-workshop`。
2. 将本目录内容上传到仓库根目录，确保根目录有 `index.html`。
3. 在 Settings → Pages → Build and deployment 中选择 Deploy from a branch。
4. Branch 选择 `main`，文件夹选择 `/(root)`，保存。
5. 等待 Pages 构建完成，以设置页显示的实际网址为准。

## 经营天数自动同步与合规明细

在“对手方工商数据”中设置报告结束日期，保留原经营开始时间，经营天数自动按“报告结束日期－原经营开始时间”计算，不额外加一天。导入旧版 JSON、ZIP 或工商 Excel，或切换报告期间，都会自动同步，无需预览和批量应用。

原始记录不改写：保存项目 JSON 保留原经营开始时间、导入原天数及风险数量；页面、报告和工商导出使用新计算天数，原天数仅供对照，不参与计算。开始日期缺失、无效或晚于报告结束日期时，计算结果为空并在日期核验中说明，不使用旧天数补值。原经营开始时间及其他工商字段保持不变。

“下载全部工商及合规数据”包含8张表：对手方工商档案、导入原始工商档案、诉讼明细、失信被执行人明细、行政处罚明细、合规数量核验、经营日期自动核验、数据说明。三类明细也可分别全部下载；全部下载不受页面筛选影响，整套测试数据 ZIP 同样包含这些资料。

诉讼和行政处罚按原数量逐条生成，失信“是”生成1条、“否”生成0条。未提供或无效数量保留缺失，不回填原字段。案号及文书内容为用于核对条数的测试明细，不是企业真实风险资料。重新导入含原始和同步档案的 Excel 时，优先恢复原始档案，再按当前报告结束日和原经营开始时间重新计算天数。

## 命令更新页面

报告封面“被审计单位主档”状态仅核对主档是否覆盖所选期间流水中的本方单位：覆盖则已上传，缺单位则部分缺失，没有主档记录则未上传。公司职能等字段及其他主档的额外单位不影响此状态。

报告汇总金额单位统一为“百万”，汇总表头使用“金额（百万）”“笔数（笔）”“占比（%）”（有流入、流出等前缀时保留）。占比单元格和核验 Excel 使用百分数数字，例如25%显示25.00，百分号放在表头。大额单笔、交易对手方为空、摘要为空的流水明细仍按元显示；原上传模板及流水明细金额不转换。

关联方汇总同时展示名称数和组合数。关联组合按“被审计单位公司名称＋关联方名称”去重，补齐不同被审计单位之间双向组合；不自动添加自己与自己的组合，不扩展第三方关系。报告和核验 Excel 可查看主档组合、自动补齐及最终组合明细；原上传主档不被改写。

本地已连接仓库后，使用 Git 命令提交并推送。账号统计按本期流水中的被审计单位公司＋账号去重。银行账号清单和科目余额表来源：本期资料有该账号，但所选期间没有本方流水，才列缺失，其他期间有流水不代替本期。流水有而清单、余额表没有的账号不计入这两类。缺失同名账户仍按同一工作簿全部流水判断。同一账号命中多个来源时分类分别计数，账号总数去重。

源码位于 `src/`。修改后运行：

```sh
node build.mjs
cp dist/index.html index.html
```

提交并推送更新后的源码和根目录 `index.html`；Pages 会重新部署。Node.js 只用于打包，访问者无需安装。

```sh
git add src/report.js index.html README.md .nojekyll
git commit -m "Update account completeness checks"
git push origin main
```

## 本地使用

用现代浏览器打开 `index.html` 即可使用。浏览器只自动保留部分设置，切换网址、浏览器或设备不会自动同步项目；离开前下载项目 JSON。

## 发布内容

本目录仅包含工作坊程序、内置测试样本、构建脚本及依赖许可证。不包含工作目录中的测试用例 Excel、用户导出的项目或其他附件。


## Excel 模板转项目

顶部「Excel 模板转项目」支持平台导出的9类主档／流水和对手方工商Excel，无需手工编写JSON。可以下载一个包含所有工作表的空白模板，也可以多选各个Excel或上传ZIP。表名、文件名或完整模板表头用于识别；列可以调整顺序，必需列缺失会阻止导入。

选择文件后先检查记录数、缺少的模板和格式提醒，再点击确认。创建新项目时未提供的表留空；更新当前项目时只替换已识别的类型。同类主档或流水分在多个文件中时按选择顺序合并，不自动去重。工商数据优先使用「导入原始工商档案」，跨文件完全相同的工商记录只导入一次。辅助核验资料不作为上传数据重复导入。

账号、税号及员工编号请在Excel中使用文本。保留空白字段、已有余额异常和已有等值人民币金额，不重新生成流水、不在确认导入时重算汇率金额。经营天数仍按现有工商规则由经营开始时间计算。确认后点击「下载转换后的项目 JSON」保存完整项目，下次可直接用原JSON入口恢复。Excel不携带生成规则、汇率或报告筛选设置，需要在页面确认。

回归检查：`node tests/template-import.cjs`。原JSON v1/v2导入路径保持独立。


## 集中度排名口径

所选期间先剔除对手方属于被审计单位的内部往来，再按对手方名称汇总，在全体外部对手方中按流入金额、流出金额分别统一排名；取前5、前10、前20后才拆客户／供应商／客商一体／非客商及关联方／第三方。空白名称作为一个对手方参与排名，归入非客商第三方。占比分母仍为同方向、同客商分类的总金额。报告按前5、第6–10、第11–20、非前20显示不重叠区间；核验明细给出统一排名。此口径修正会改变旧项目的集中度核验结果，不改旧项目原始数据。
