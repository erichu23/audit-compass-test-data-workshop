# Audit Compass 测试数据工作坊

浏览器内运行的测试数据生成及综合分析报告核验工具。主档、流水、工商测试数据、计算、Excel/ZIP/Word 导出均在本机浏览器完成，无业务后端或数据库。

## 数据说明

内置企业名称用于测试，交易、关联关系、人员及工商风险信息为测试样本，不代表相关企业的真实交易、关联关系或风险。内置样本会随页面源代码一起发布。用户自行导入的数据仅在浏览器中处理，不会通过应用接口上传；完整项目需使用“保存项目”下载后保管。

## GitHub Pages 部署

1. 新建仓库 `audit-compass-test-data-workshop`。
2. 将本目录内容上传到仓库根目录，确保根目录有 `index.html`。
3. 在 Settings → Pages → Build and deployment 中选择 Deploy from a branch。
4. Branch 选择 `main`，文件夹选择 `/(root)`，保存。
5. 等待 Pages 构建完成，以设置页显示的实际网址为准。

## 经营天数自动同步与合规明细

在“核验设置”中设置工商计算截止日期，保留原经营开始时间，经营天数自动按“报告结束日期－原经营开始时间”计算，不额外加一天。导入旧版 JSON、ZIP 或工商 Excel，或切换报告期间，都会自动同步，无需预览和批量应用。

原始记录不改写：保存项目 JSON 保留原经营开始时间、导入原天数及风险数量；页面、报告和工商导出使用新计算天数，原天数仅供对照，不参与计算。开始日期缺失、无效或晚于报告结束日期时，计算结果为空并在日期核验中说明，不使用旧天数补值。原经营开始时间及其他工商字段保持不变。

“下载全部工商及合规数据”包含8张表：对手方工商档案、导入原始工商档案、诉讼明细、失信被执行人明细、行政处罚明细、合规数量核验、经营日期自动核验、数据说明。三类明细也可分别全部下载；全部下载不受页面筛选影响，整套测试数据 ZIP 同样包含这些资料。

诉讼和行政处罚按原数量逐条生成，失信“是”生成1条、“否”生成0条。未提供或无效数量保留缺失，不回填原字段。案号及文书内容为用于核对条数的测试明细，不是企业真实风险资料。重新导入含原始和同步档案的 Excel 时，优先恢复原始档案，再按当前报告结束日和原经营开始时间重新计算天数。

## 命令更新页面

报告封面“被审计单位主档”状态仅核对主档是否覆盖所选期间流水中的本方单位：覆盖则已上传，缺单位则部分缺失，没有主档记录则未上传。公司职能等字段及其他主档的额外单位不影响此状态。

报告汇总金额单位统一为“百万”，汇总表头使用“金额（百万）”“笔数（笔）”“占比（%）”（有流入、流出等前缀时保留）。占比单元格和核验 Excel 使用百分数数字，例如25%显示25.00，百分号放在表头。大额单笔、交易对手方为空、摘要为空的流水明细仍按元显示；原上传模板及流水明细金额不转换。

关联方汇总同时展示名称数和组合数。关联组合按“被审计单位公司名称＋关联方名称”去重，补齐不同被审计单位之间双向组合；不自动添加自己与自己的组合，不扩展第三方关系。报告和核验 Excel 可查看主档组合、自动补齐及最终组合明细；原上传主档不被改写。

本地已连接仓库后，使用 Git 命令提交并推送。账号统计按本期流水中的被审计单位公司＋账号去重。银行账号清单和科目余额表来源：本期资料有该账号，但所选期间没有本方流水，才列缺失，其他期间有流水不代替本期。流水有而清单、余额表没有的账号不计入这两类。缺失同名账户仍按同一工作簿全部流水判断。同一账号命中多个来源时分类分别计数，账号总数去重。

源码位于 `src/`。修改后运行：

```sh
node build.mjs
cp dist/index.html index.html
```

提交并推送更新后的源码和根目录 `index.html`；Pages 会重新部署。Node.js 只用于打包，访问者无需安装。

```sh
git add src/report.js index.html README.md .nojekyll
git commit -m "Update account completeness checks"
git push origin main
```

## 本地使用

用现代浏览器打开 `index.html` 即可使用。浏览器只自动保留部分设置，切换网址、浏览器或设备不会自动同步项目；离开前下载项目 JSON。

## 发布内容

本目录仅包含工作坊程序、内置测试样本、构建脚本及依赖许可证。不包含工作目录中的测试用例 Excel、用户导出的项目或其他附件。


## Excel导入

左侧「导入数据 → Excel导入」支持平台导出的9类主档／流水和对手方工商Excel，无需手工编写JSON。可以下载一个包含所有工作表的空白模板，也可以多选各个Excel或上传ZIP。表名、文件名或完整模板表头用于识别；列可以调整顺序，必需列缺失会阻止导入。

选择文件后先检查记录数、缺少的模板和格式提醒，再点击确认。创建新项目时未提供的表留空；更新当前项目时只替换已识别的类型。同类主档或流水分在多个文件中时按选择顺序合并，不自动去重。工商数据优先使用「导入原始工商档案」，跨文件完全相同的工商记录只导入一次。辅助核验资料不作为上传数据重复导入。

账号、税号及员工编号请在Excel中使用文本。保留空白字段、已有余额异常和已有等值人民币金额，不重新生成流水、不在确认导入时重算汇率金额。经营天数仍按现有工商规则由经营开始时间计算。确认后点击「下载转换后的项目 JSON」保存完整项目，下次可直接用原JSON入口恢复。Excel不携带生成规则、汇率或报告筛选设置，需要在页面确认。

回归检查：`node tests/template-import.cjs`。原JSON v1/v2导入路径保持独立。


## 集中度排名口径

所选期间先剔除对手方属于被审计单位的内部往来，再按对手方名称汇总，在全体外部对手方中按流入金额、流出金额分别统一排名；取前5、前10、前20后才拆客户／供应商／客商一体／非客商及关联方／第三方。空白名称作为一个对手方参与排名，归入非客商第三方。占比分母仍为同方向、同客商分类的总金额。报告按前5、第6–10、第11–20、非前20显示不重叠区间；核验明细给出统一排名。此口径修正会改变旧项目的集中度核验结果，不改旧项目原始数据。


## 报告客商分类

1.3集中度、2.1对手方类型及后续识别结果统一按整套客户／供应商主档中的对手方名称分类，不因流水本方单位不同而拆成多类。仅客户表有为客户，仅供应商表有为供应商，两表都有为客商一体，两表都没有（含空白）为非客商。关联关系统一按整套关联方主档的对手方名称匹配，不要求本方公司一致。命中即关联方，类型为空显示其他；未命中为第三方。同名多条类型去重合并展示，交易只统计一次。此报告口径不重写已保存项目中的流水标签与原始数据。


区间版本3：所有分布区间统一左闭右开，最后一档为≥最后分界值。工商经营时间、参保人数、注册资本及大额单笔、未识别客商交易额的边界值进入后一档；收支重合比例原本已符合此规则。原始数据及自定义分界值保留，旧项目重新计算时使用新边界归属。


1.3集中度分类允许交叉：客商一体同时计入客户、供应商及客商一体；排名先按每个对手方实际金额计算一次，再展开分类。分类占比分母为该列同方向全部金额（含客商一体），列之间不能直接相加。月度分类柱图使用相同交叉口径。2.1左侧柱图和分类表也采用交叉口径，客商一体同时计入客户、供应商和客商一体；占比分母仍为本期剔除内部往来后的同方向去重交易总额，分类合计可能超过100%。右侧前20大清单按名称去重、只展示一次。


2.2关联方交易按本方被审计单位＋对手方组合匹配，只计入命中组合的流水，再按对手方汇总排名取前20。关联类型分别统计，不拼接成新类型；重复主档的相同类型去重。多类型的交易会出现在各类型，图表类型合计存在交叉，交易总额和清单不重复。1.3及2.1继续按对手方名称判断关联性质。


2.3.3收支重合包含单向交易，比例为0归第一档；流入流出均为0的对象不参与收支重合分布。空白名称合并为一个对手方参与收支重合和未识别客商分析，按未匹配客商处理。未识别客商逐笔按本方单位＋对手方组合匹配，仅将客户、供应商主档均未命中的流水按对手方名称汇总，同名对手方其他已匹配流水不计入该分析。图表分段与下方系统筛选结果仍分开计算。


当前1.3集中度：先按对手方名称汇总实际金额、统一排名，取排名段后再按本方单位＋对手方组合匹配客户供应商主档、分类汇总。不同本方的同名对手方可有不同客商分类。仅同一组合同时命中客户和供应商时交叉计入三列，分母为该组合匹配口径下同方向同分类总金额。月度图同口径。1.3关联性质仍按名称判断；2.1保持既有名称匹配及排名口径，不受此调整影响。


2.1左侧柱图及全部交易对手方分类表已同步1.3的本方单位＋对手方客商匹配口径，金额与笔数可与1.3分类合计对照；同一组合的客商一体交叉计入三列。关联性质仍按名称。2.1占比分母仍为同方向外部交易总额，1.3为对应分类总额。右侧前20排名、金额及全局名称客商标签保留，不能用右侧标签直接汇总核对左侧组合分类。


2.1右侧前20大客商标签也按本期本方＋对手方组合汇总，合并展示实际类型（例如客户、非客商），不会把不同本方的客户／供应商身份自动合成客商一体。仍按名称只列一行且排名金额不变，多标签行金额不可完整重复归入每一标签；左侧分类金额应以逐笔组合拆分结果核对。


## 每日汇率主档（可选，兼容旧项目）

左侧「导入数据 → 每日汇率」支持上传Excel，三列表头固定为「生效日期」「货币名称」「汇率」。可下载空白模板；支持ISO三位币种代码和美元、港币、日元等常用名称。每个币种单独指定报价单位，例：JPY报价4.47947、报价单位100，实际乘数为0.0447947；USD等币种可设报价单位1。人民币始终按1。

流程：先导入主档和流水，再上传汇率表；检查报价单位和日期覆盖，点击应用，最后保存项目JSON。上传仅暂存，应用前不改变当前核验。固定汇率与每日汇率可切换。每日汇率有三种缺失处理：

- 精确匹配：交易日期当天必须有该币种汇率，启用前检查当前全部流水，缺失需先补齐。
- 最近生效：选择不晚于交易日期的最近一条汇率，绝不使用未来日期；此前无记录仍阻止启用。
- 缺失用原币：只对没有当日汇率的流水按原币数值计入（乘数1），已有当天汇率仍正常换算。存在这类流水的报告与核验说明标记为混合口径，不能当作纯人民币总额。

外币注册资本／实缴资本按工商计算截止日期匹配每日汇率，日期独立于银行报告期间；如果仍缺失，不使用原币混加资本统计，显示未提供。银行余额按选中流水自身交易日换算，未另做期末统一重估。

原始主档、流水、导入人民币列和原始工商数据不改写。每日换算金额用于派生核验结果，核验Excel附带「每日汇率主档」「逐笔汇率换算明细」；明细含源流水行、交易日期、生效日期、主档原始报价、报价单位、实际汇率、匹配来源、换算金额及保留的导入人民币金额。设置页还能导出全部流水的换算／缺失明细。主档同日同币种相同值去重，冲突值、无效日期和非正汇率阻止导入；Excel汇率保留小数显示精度，兼容1900／1904日期系统。

项目仍使用version 2及原来的data、template结构。只有使用每日汇率时在config增加可选字段fxMode、dailyFx、dailyFxUnits、dailyFxRule；旧JSON没有这些字段时固定汇率行为保持不变，导入旧项目会清除当前会话继承的每日配置。新JSON包含主档和报价设置，重新导入可恢复；还可通过撤销恢复之前汇率模式。网页本地设置不缓存完整每日主档，请保存项目JSON。整套ZIP包含汇率Excel及项目配置。

回归：`node tests/daily-fx.cjs`、`node tests/daily-fx-project.cjs`、`node tests/daily-fx-controls.cjs`、`node tests/daily-fx-excel.cjs`。Excel读取测试用Python作为XML测试适配器，产品本身仍为纯前端、无业务后端。


## 工商表头映射导入

在左侧「导入数据 → 工商数据导入」，上传第一行为表头的工商Excel，选择工作表，为平台字段指定来源列。常见列名会自动推荐；只有对手方名称必填，其他字段可以不导入。注册／实缴资本可分别指定元、万元、百万、亿元来源单位，日期支持Excel日期及常见日期文本。

先检查并预览转换结果，再确认导入；校验错误时不部分写入。默认按名称更新已映射字段并新增档案，保留未映射的旧字段、其他档案及所有主档／流水。已映射但空白的来源字段会清空旧值；也可明确选择替换全部工商档案。重复名称默认报错，可选择保留第一条／最后一条。

「记住此映射」只在当前浏览器保存列名对应关系与单位设置，不保存源数据。可下载转换后的标准工商Excel，确认导入后保存项目JSON。此入口沿用原工商数据结构，不增加JSON必填字段，原标准模板及旧JSON导入继续使用原入口。经营天数继续按原经营开始时间和工商计算截止日期派生，导入原值仅供对照。


对手方为空交易统一按“对手方名称为空（含空值、空字符串和纯空格）”判断；即使对手方账号有值也计入。首页、逐年覆盖、核验报告及导出使用同一口径；报告仍限定所选期间和币种。旧项目导入后直接按此规则重算，原始名称、账号及流水不改写。


每日汇率上传新增币种名称映射：三位币种代码无需在常用币种白名单内；内置常见名称自动推荐，其他自定义名称可手动对应到三位代码。同一名称的所有日期一次映射，预览保留来源名称。映射后的记录及来源别名随原有dailyFx记录保存，旧JSON无新增必填字段。来源别名也可匹配流水中相同名称，不修改流水币种原值。

逐笔换算按交易日期＋映射后的币种查找，上传的全部日期均建立索引；不会统一取年末或最后一天汇率。“精确匹配”“最近生效”“缺失按原币”仍分别执行原规则。检查覆盖后可下载全部逐笔换算明细，其中列出交易日期、实际使用的汇率生效日期、主档报价、报价单位及实际汇率。


## 项目工作台与导入界面

首页展示当前资料记录数、当前生效的分析期间、金额口径、汇率方式和独立的工商计算截止日期。侧栏依次为导入数据、生成／修改数据、当前数据、功能验证；打开和保存项目保留在右上角。资料“有记录／空表”仅描述浏览器中现有数据，不替代原报告中的资料完整性核验。

Excel导入提供9类文件的用途说明、空白模板、已选文件、识别清单和每类记录数。状态分为读取中、待确认、需要修正、已导入；未提供的表明确显示新建时留空或更新时保留。文件读取失败会在页面保留原因。工商及每日汇率仍有各自独立的导入入口。

核验设置复用原报告期间控件、原工商日期／区间控件及原重点事项筛选表单；预览与核对展示报告正文，报告导出集中选择格式和章节。所有设置继续使用原来的应用操作，浏览页面不自动修改配置。

此次界面改版不修改计算、汇率、工商、Excel解析和Word导出模块；项目JSON结构、Excel识别与确认导入函数保持原样。界面文件状态只保留在当前页面会话，不写入项目JSON。兼容验收比较同一项目在改版前后、相同参数下的原始记录、配置、模板及报告数值。


## 测试数据与功能验证

测试工作台提供两条准备路径：生成／修改测试数据，或导入已有数据。两者使用同一当前项目；Excel导入完成后可选择继续修改数据或进入功能验证，不另建一份隐式数据副本。生成页面明确展示正在操作的项目与流水笔数，并提供查看当前数据、保存项目和进入功能验证的入口。

功能验证是可扩展的功能入口，本版本提供报告核验。报告的核验设置、预览与导出属于该功能内部；场景覆盖检查仍用于数据生成检查。后续功能可从功能列表扩展。

此次流程调整只修改导航、展示及入口。旧JSON的原始记录、生成底稿、核验配置及原有导入／计算逻辑不变；打开项目或进入生成页面不会自动重新生成流水，也不会以当前流水覆盖旧项目保存的生成底稿。实际编辑或生成仍执行原有操作规则。


综合分析报告核验：分析期间、金额口径、导出章节及操作按钮恢复到报告正文上方；工商计算日期和统计区间在同页上方展开查看。原“核验设置”入口跳转到该页，不再需要切换独立设置页面。功能列表与导航统一使用“综合分析报告核验”，报告内容、数据与计算口径不变。
